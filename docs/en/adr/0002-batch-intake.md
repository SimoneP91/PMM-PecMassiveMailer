# ADR 0002 — Batch intake

**Date**: 2026-09-19 · **Status**: accepted

## Context

`POST /v1/batches` is the contract the whole service exists for: one call, one template, one mailbox, up to 2,500 recipients with their own values and files. It must be impossible to create a batch by accident twice, to send anything but a PEC, or to let a recipient's data change the meaning of the HTML.

## Decisions

| Decision                                                                                                       | Reason                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| One `multipart/form-data` call: a `batch` JSON part plus one part per file                                     | Every client language does this natively (PHP cURL included); a file shared by all rows is uploaded once. The alternative, "we download your URLs", is an SSRF vector and was rejected.                                                                                                          |
| Files streamed to a staging directory while hashed, then renamed under the batch                               | Never in memory; a rejected request leaves nothing behind (staging removed in every error path).                                                                                                                                                                                                 |
| Messages stored **rendered** (subject and body per row), template kept on the batch for reference              | What is stored is exactly what will be sent and what the client reads back; the worker needs no template engine.                                                                                                                                                                                 |
| Row-level rejection by default, `options.atomic` to refuse everything                                          | A batch of 1,000 with two bad rows should not block 998 legal notices; a client that prefers all-or-nothing says so. `ALL_MESSAGES_REJECTED` is a `422`: a batch with zero rows is not created.                                                                                                  |
| Batch-level problems are `4xx` and create nothing; row-level problems are listed in the `202`                  | One rule the client can rely on: an error status means "nothing happened".                                                                                                                                                                                                                       |
| `Idempotency-Key` mandatory, fingerprint = JSON + every file (name, size, SHA-256)                             | A timeout must not become two batches. The record is inserted as a lock before work starts, so an overlapping retry gets `409 IDEMPOTENCY_IN_PROGRESS`; a failed attempt removes the lock so the key can be retried. Not required for `dryRun`, which creates nothing.                           |
| `dedupKey` unique per tenant across batches, checked before insert and enforced by a partial unique index      | Belt and braces: the pre-check gives a precise per-row error naming the earlier message; the index catches the race between two concurrent batches (`409 DEDUP_KEY_CONFLICT`, transaction rolled back).                                                                                          |
| Batch + messages in one MongoDB transaction                                                                    | A crash between the two inserts must not leave PENDING messages for a batch that does not exist — the worker would send them. This is why the replica set is required even locally.                                                                                                              |
| HTML allowlist, **reject never sanitise**; `{{name}}` escaped, `{{{name}}}` raw but re-validated per row       | Legal value: what goes out is what the client wrote, or nothing, with a list of what was wrong. A value can only land in text or in a quoted attribute; placeholders as tag names, unquoted attribute values, inside `<style>` or comments are rejected because escaping does not protect there. |
| Remote images forbidden, `cid:` inline images only                                                             | A remote image is an open-tracking pixel and a privacy problem in a certified communication.                                                                                                                                                                                                     |
| Recipient verification by provider domain lists and MX lookup, `UNDETERMINED` refused by default               | A PEC to a non-PEC address is accepted by the provider and never delivered. Lists are a curated starting point (not the AgID registry) and extensible from the config file; unknown means "ask the client", never "assume PEC".                                                                  |
| File type from the first bytes with an extension allowlist; "dispatcher, not a scanner"                        | Refuse the plainly wrong (an executable named `.pdf`, a `.bat`), accept documents. Antivirus is the platform's job.                                                                                                                                                                              |
| Per-message size estimated after base64 (4/3 + overhead), checked against the mailbox limit at intake, per row | Cheaper than a rejection from the SMTP server hours later; row-level rather than the `413` originally sketched, because with `atomic: false` one oversized row should not sink the batch.                                                                                                        |
| In-memory MongoDB replica set for e2e tests                                                                    | The intake is transactions + indexes + real multipart parsing; mocking any of it would test the mock. `mongodb-memory-server` downloads the binary once.                                                                                                                                         |

## Consequences

- The worker (stage 3) reads `messages` with `status: PENDING` ordered by `nextAttemptAt`, per mailbox, and finds the files at `parts[].path` under `STORAGE_DIR`.
- Read endpoints (stage 4) already have their indexes: `tenantId` + `createdAt`/`reference`/`subTenant`/`status` on batches, `tenantId` + `to`/`ref`/`subTenant`/`status` on messages.
- The provider lists need a review against the AgID registry before the first production tenant; until then `options.unverifiedRecipients = "send"` is the escape hatch for a legitimate domain the lists do not know.
